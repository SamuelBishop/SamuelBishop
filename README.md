I'm a Software Engineer II at Microsoft, building **Dynamics 365 Customer Service** and the AI experiences around it. I mainly work with **React, TypeScript, C#, .NET, and Azure**. The interface people use, the services, integrations, and telemetry behind them all.

Lately, that means connecting Dynamics 365 with **Microsoft Copilot, Cowork, and Copilot Studio**, building agent experiences through **MCP**, and figuring out how to evaluate whether those agents actually do what they're supposed to.

## What I work on

- **Enterprise AI:** agent integrations, tool access, embedded widgets, and the authentication and governance that make them usable in real organizations.
- **Agent evaluation:** intent matching, instruction adherence, response telemetry, and working with customer engineers to test real workflows.
- **Frontend platforms:** reusable components, rich text editing, accessibility, extensibility, and secure rendering. I've helped build the modern editor used by **2.3 million monthly active users**.
- **Real-time systems:** messaging infrastructure with Azure SignalR, WebSockets, Service Fabric, and Service Bus. My Microsoft internship started with building the Agent Backbone Service from the ground up.
- **Production engineering:** Kusto investigations, browser debugging, incident response, and turning what we learn from failures into tests, tooling, and runbooks.

Earlier, I worked on embedded graphics for **Garmin's G3000 flight deck**. I studied electrical engineering and computer engineering at **Mizzou**, so I still enjoy problems that cross the boundary between software and hardware.

## AI-assisted development

This is where a lot of my curiosity goes right now.

```text
  codex  ~  claude  ~  github copilot
```

I use coding agents daily for implementation, refactoring, debugging, and review. I'm especially interested in:

- Designing workflows that hold up in large, unfamiliar codebases.
- Giving agents the right context through retrieval, RAG, and useful tools.
- Keeping context and token usage lean without losing the information needed to do the job.
- Comparing models on real engineering tasks: correctness, latency, cost, and how much cleanup they leave behind.
- Building evaluations and feedback loops that make agent behavior easier to inspect and improve.

I like working through the whole loop: understand the problem, build something, test it, see where it breaks, and make it better.
